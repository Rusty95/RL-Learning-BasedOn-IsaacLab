Actor-Critic 算法：一边行动，一边评价

Actor 像“决策者”，负责选动作；Critic 像“教练”，负责估计这个动作之后的长期价值。两者互相配合，让策略更新不再只靠稀疏、吵闹的回报信号。

先抓住直觉

Actor

负责“怎么做”

Actor 是策略函数 π。输入状态后，它输出动作或动作概率分布。训练目标是让高回报动作更常被选中，让低回报动作逐渐淡出。

Critic

负责“好不好”

Critic 是价值函数 V 或 Q。它不直接控制行为，而是预测当前状态未来能拿到多少总回报，用来给 Actor 提供更稳定的学习信号。

Advantage

负责“比预期好多少”

优势函数 A(s,a) 衡量某个动作相对平均水平的超额收益。优势为正，Actor 增大该动作概率；优势为负，Actor 降低该动作概率。

强化学习问题先长什么样？

Actor-Critic 解决的是序贯决策问题：智能体不是只做一次分类，而是在一串状态里不断行动，每一步都会改变未来能看到什么、能拿到多少奖励。通常我们把这个过程写成马尔可夫决策过程 MDP。

马尔可夫性的意思是：只要当前状态 s 描述得足够完整，未来就不需要再依赖更早的历史。真实任务里状态常常不完美，所以还会用 RNN、历史堆叠或 belief state 补信息。

状态 s
环境当前信息，比如小车位置、速度，机器人传感器读数，或游戏画面特征。
动作 a
智能体可选的行为。离散动作像上下左右，连续动作像电机力矩或转向角。
奖励 r
环境给出的即时反馈。奖励设计会极大影响训练效果，太稀疏或有漏洞都会让策略学歪。
折扣因子 γ
控制未来奖励的重要程度。γ 接近 1 更看重长期收益，γ 小则更短视但训练目标通常更稳定。

一次训练循环

  1. 观察状态

    智能体拿到环境状态 s，比如机器人关节角、游戏画面、库存水平，或任何可用于决策的信息。

  2. Actor 采样动作

    策略 π(a|s) 产生动作。训练时通常保留随机性，用探索避免太早陷入一个看似不错但并不最优的行为。

  3. 环境返回奖励

    执行动作后得到 r 和 s'。奖励可以很短视，但价值函数会把它和未来收益合起来看。

  4. Critic 计算 TD 误差

    TD 误差 δ 表示“实际看到的目标”与 Critic 当前预测之间的差距。它既训练 Critic，也常被当作 Actor 的优势估计。

  5. 同时更新两套网络

    Critic 学会更准地估值；Actor 用 Critic 给出的信号调整策略。一个管判断，一个管行动，闭环就转起来了。

从 Policy Gradient 到 Actor-Critic

策略梯度的目标是最大化期望回报：让参数 θ 控制的策略 πθ 在采样轨迹后拿到更高总奖励。最朴素的 REINFORCE 会用整条轨迹的回报 Gt 去乘上动作对数概率的梯度。

目标J(θ) = E[Σt γt rt] 策略梯度∇J(θ) ≈ Σt ∇θ log πθ(at|st) · Gt

问题在于 Gt 方差很大：一次运气好可能让错误动作也被奖励，一次运气差也可能惩罚了好动作。训练会像在噪声里听音乐，旋律有，但不清楚。

Actor-Critic 的改造

它引入 Critic 学一个 baseline：当前状态本来就大概值多少。Actor 更新时不再问“这次总回报是多少”，而是问“这次动作比当前状态的平均预期好多少”。

优势定义A(s,a) = Q(s,a) - V(s) 常用近似A(st,at) ≈ δt

这就是为什么 Critic 能降低方差：它把“环境本来就容易/困难”的部分扣掉，让 Actor 更关注动作本身的贡献。

核心公式

最常见的 Actor-Critic 会用 Critic 的价值估计来降低策略梯度的方差。下面是基于状态价值 V(s) 的版本。

TD 目标y = r + γ V(s') TD 误差δ = y - V(s) Critic 损失Lc = 12 · δ2 Actor 目标maximize log π(a|s) · δ Actor 更新θ ← θ + αactor · ∇θ log πθ(a|s) · δ Critic 更新w ← w - αcritic · ∇w Lc

关键点：如果 δ > 0，说明结果比 Critic 预期好，Actor 会更偏向刚才的动作；如果 δ < 0，说明结果低于预期，Actor 会减少这个动作的概率。

例子 1：结果更好

Critic 预测 V(s)=0.4，实际目标 y=0.7，则 δ=+0.3。Actor 会强化刚才的动作。

例子 2：结果更差

Critic 预测 V(s)=0.8，实际目标 y=0.5，则 δ=-0.3。Actor 会减少刚才动作的概率。

例子 3：预期准确

如果 y≈V(s)，δ 接近 0，说明动作没有明显超预期，Actor 更新幅度会很小。

伪代码：把算法跑起来

初始化 Actor 参数 θ，Critic 参数 w for episode = 1 ... N: 重置环境，得到初始状态 s while episode 未结束: 用 Actor 采样动作 a ~ πθ(a|s) 执行动作，得到 r, s', done # Critic: 估计这一步的 TD 目标和误差 if done: y = r else: y = r + γ Vw(s') δ = y - Vw(s) # 更新 Critic，让 Vw(s) 更接近 y minimize 1/2 * δ² # 更新 Actor，让高优势动作概率上升 maximize log πθ(a|s) * stop_gradient(δ) s = s'

实现时通常会对 δ 或 advantage 做 detach / stop_gradient，因为 Actor 更新只希望把 δ 当作评价信号，不希望 Actor 的损失反向穿过 Critic 的网络参数。

完整代码实现：一步一步写 Actor-Critic

下面是一份最小但完整的 PyTorch 风格实现，适合离散动作环境，比如 CartPole。它展示的是 online one-step Actor-Critic：每和环境交互一步，就更新一次 Actor 和 Critic。

import gymnasium as gym import torch import torch.nn as nn import torch.optim as optim from torch.distributions import Categorical class Actor(nn.Module): def __init__(self, state_dim, action_dim): super().__init__() self.net = nn.Sequential( nn.Linear(state_dim, 128), nn.ReLU(), nn.Linear(128, action_dim) ) def forward(self, state): logits = self.net(state) return Categorical(logits=logits) class Critic(nn.Module): def __init__(self, state_dim): super().__init__() self.net = nn.Sequential( nn.Linear(state_dim, 128), nn.ReLU(), nn.Linear(128, 1) ) def forward(self, state): return self.net(state).squeeze(-1) env = gym.make("CartPole-v1") state_dim = env.observation_space.shape[0] action_dim = env.action_space.n actor = Actor(state_dim, action_dim) critic = Critic(state_dim) actor_optimizer = optim.Adam(actor.parameters(), lr=1e-3) critic_optimizer = optim.Adam(critic.parameters(), lr=1e-3) gamma = 0.99 episodes = 600 for episode in range(episodes): state, _ = env.reset() done = False episode_reward = 0 while not done: state_tensor = torch.tensor(state, dtype=torch.float32).unsqueeze(0) # 1. Actor 根据当前状态输出动作分布，并采样动作 dist = actor(state_tensor) action = dist.sample() log_prob = dist.log_prob(action) # 2. 环境执行动作，返回奖励和下一个状态 next_state, reward, terminated, truncated, _ = env.step(action.item()) done = terminated or truncated episode_reward += reward reward_tensor = torch.tensor([reward], dtype=torch.float32) next_state_tensor = torch.tensor(next_state, dtype=torch.float32).unsqueeze(0) done_tensor = torch.tensor([done], dtype=torch.float32) # 3. Critic 估计 V(s) 和 V(s') value = critic(state_tensor) with torch.no_grad(): next_value = critic(next_state_tensor) td_target = reward_tensor + gamma * next_value * (1 - done_tensor) # 4. TD error 既是 Critic 的学习目标，也是 Actor 的 advantage 估计 td_error = td_target - value # 5. 更新 Critic：让 V(s) 靠近 td_target critic_loss = td_error.pow(2).mean() critic_optimizer.zero_grad() critic_loss.backward() critic_optimizer.step() # 6. 更新 Actor：正 advantage 增大动作概率，负 advantage 减小动作概率 actor_loss = -(log_prob * td_error.detach()).mean() actor_optimizer.zero_grad() actor_loss.backward() actor_optimizer.step() state = next_state if episode % 20 == 0: print(f"episode={episode}, reward={episode_reward}")
Actor 类

输出动作分布

Actor 不是直接输出“选哪个动作”，而是输出每个动作的 logits，再交给 Categorical 形成概率分布。这样既能采样探索，也能计算 log_prob 用于策略梯度。

Critic 类

输出状态价值

Critic 输入状态 s，输出一个标量 V(s)。这个值表示“从当前状态开始，未来折扣回报大概是多少”。它越准，Actor 得到的 advantage 信号越可靠。

两个优化器

分开更新更清楚

Actor 和 Critic 各有自己的 optimizer。这样可以分别调学习率，也能避免两个网络的梯度混在一起，代码结构更容易 debug。

代码位置 在算法里对应什么 为什么这样写
dist = actor(state_tensor)
action = dist.sample()		 Actor 根据 π(a|s) 选择动作。 训练时需要探索，所以从概率分布采样，而不是永远选最大概率动作。
log_prob = dist.log_prob(action) 策略梯度里的 log π(a|s)。 Actor loss 会用它乘 advantage：好动作提高概率，坏动作降低概率。
td_target = r + γV(s') Critic 的 bootstrap 目标。 不用等整局结束，每一步都能估计“即时奖励 + 下一状态价值”。
td_error = td_target - value TD error，也是一阶 advantage 估计。 它告诉 Actor：这次动作的结果比预期好还是差。
critic_loss = td_error.pow(2).mean() 训练 Critic。 让 V(s) 逼近 td_target，本质是一个回归问题。
actor_loss = -(log_prob * td_error.detach()).mean() 训练 Actor。 前面的负号是因为 PyTorch optimizer 默认最小化 loss，而策略目标是最大化 log_prob * advantage。

最重要的一行：td_error.detach()。Actor 更新时只把 TD error 当作“评分”，不让 Actor loss 的梯度反向穿过 Critic。否则 Actor 的优化会顺手改变 Critic 相关计算图，学习目标会变得混乱。

为什么不用纯 Policy Gradient？

纯策略梯度

直接用完整回报 G 来更新策略，概念简单，但回报波动大，尤其在奖励稀疏或轨迹很长时，训练会很吵。

Actor-Critic

用 Critic 提供 baseline 或 advantage，通常方差更低、学习更快，也更容易扩展到连续动作和大规模神经网络。

Bias 与 Variance：它真正权衡的东西

方法 学习信号 优点 缺点
Monte Carlo Policy Gradient 完整轨迹回报 Gt 估计无偏，理论直观，不需要价值函数 bootstrap。 方差高，要等 episode 结束，长任务和稀疏奖励里训练慢。
TD Actor-Critic r + γV(s') - V(s) 可以每一步更新，方差较低，数据效率通常更好。 Critic 如果估错会引入偏差，训练稳定性依赖价值函数质量。
GAE Actor-Critic 多步 TD 误差加权和 用 λ 在偏差和方差之间调节，是 PPO 等算法里很常见的选择。 多一个 λ 超参数，需要批量轨迹和更细致的实现。

常见变体

A2C / A3C

Advantage Actor-Critic。A3C 用多个异步 worker 探索环境，A2C 是同步版本，工程上更容易复现。

DDPG / TD3

用于连续动作控制。Actor 输出确定性动作，Critic 评价 Q(s,a)。TD3 通过双 Critic 和延迟更新提高稳定性。

PPO / SAC

PPO 用裁剪目标限制策略更新幅度；SAC 最大化奖励和策略熵，鼓励持续探索，实践中非常常用。

PPO：Actor-Critic 的下一步

PPO 全名 Proximal Policy Optimization。它仍然是 Actor-Critic：Actor 负责策略 π(a|s)，Critic 负责价值 V(s)。它真正新增的核心思想是：策略可以更新，但不能一次改得太离谱。

普通 Actor-Critic 有时会因为一次梯度更新过大，把还不错的策略突然改坏。PPO 用 clipped objective 限制新策略和旧策略的差距，让训练更稳。

一句话理解 PPO

先用旧策略收集一批数据，再用这批数据训练新策略；但如果新策略让某个动作概率变化太大，就把收益裁掉，不再鼓励继续往那个方向猛冲。

概率比率rt(θ) = πθ(at|st)πold(at|st) PPO-ClipL = E[min(rtAt, clip(rt, 1-ε, 1+ε)At)] 总损失loss = policy_loss + c1 · value_loss - c2 · entropy
ratio

新旧策略差多少

ratio 大于 1，说明新策略比旧策略更喜欢这个动作；ratio 小于 1，说明新策略降低了这个动作概率。PPO 直接盯着这个比例。

clip

限制更新幅度

如果 ε=0.2，ratio 通常被限制在 0.8 到 1.2 的有效区间。超出区间后，目标函数不再继续奖励这种过猛变化。

entropy

保持探索

entropy 越高，动作分布越不确定。PPO 常在 loss 里加入 entropy bonus，防止策略太早变成“永远选同一个动作”。

PPO 为什么要 clip？

Advantage ratio 变化 PPO 的态度 直觉
A_t > 0 ratio 从 1 涨到 1.5 最多按 1+ε 奖励，不鼓励继续暴涨。 这个动作确实好，但别因为一批数据就把概率推太猛。
A_t < 0 ratio 从 1 降到 0.4 最多按 1-ε 惩罚，不鼓励继续暴跌。 这个动作这次不好，但也别立刻把它彻底抹掉，可能只是采样噪声。
A_t ≈ 0 ratio 怎么变都影响小 更新信号很弱。 动作没有明显好坏，没必要大改策略。

GAE：PPO 里常用的 Advantage 算法

PPO 通常不是只用一步 TD error，而是用 GAE，也就是 Generalized Advantage Estimation。它把多个时间步的 TD error 按 λ 衰减相加，用来在偏差和方差之间折中。

TD 误差δt = rt + γV(st+1) - V(st) GAEAtGAE = δt + γλδt+1 + (γλ)2δt+2 + ... Returnreturnt = At + V(st)

λ 小

更接近一步 TD，方差低、偏差高，训练信号更平滑，但可能因为 Critic 估错而带来偏差。

λ 大

更接近完整 Monte Carlo 回报，偏差低、方差高。实践中 PPO 常用 γ=0.99、λ=0.95 作为起点。

PPO 训练流程

  1. 用当前策略收集 rollout

    保存状态、动作、奖励、done、动作的旧 log_prob、Critic 的 V(s)。这些旧 log_prob 后面用来算 ratio。

  2. 计算 advantage 和 return

    用 GAE 得到 A_t，再用 return_t = A_t + V(s_t) 作为 Critic 的监督目标。

  3. 多轮 mini-batch 更新

    同一批 rollout 数据会被重复训练几个 epoch。因为有 ratio 和 clip，PPO 可以比普通 on-policy AC 更安全地复用数据。

  4. 合成总损失

    Actor 用 clipped policy loss，Critic 用 value loss，策略分布再加 entropy bonus 鼓励探索。

PPO 完整计算流程

把 PPO 想成两大阶段：先用旧策略采样一批 rollout，再用这批固定数据更新多轮新策略。关键是：采样时保存的 old_log_prob、value、reward 会在更新阶段重新参与计算。

  1. 初始化策略和缓存

    Actor-Critic 接收状态维度和动作维度。以 IsaacLab Cartpole 为例，obs 通常是 [1024, 4]，actions 是 [1024, 1]。RolloutBuffer 会预分配 [num_steps, num_envs, ...] 的张量。

    obs buffer[16, 1024, 4] action buffer[16, 1024, 1] reward buffer[16, 1024] value buffer[16, 1024] log_prob buffer[16, 1024]

  2. Actor 根据当前状态采样动作

    连续动作 PPO 常用高斯策略。Actor 输出动作均值 mean，同时学习一个 log_std，组合成 Normal(mean, std)。训练时从分布采样动作，并保存该动作在旧策略下的 log 概率。

    动作均值meant = Actor(st) 动作方差std = exp(log_std) 采样动作at ~ Normal(meant, std) 旧概率old_log_probt = log πold(at|st)

    为什么要保存 old_log_prob？因为 PPO 更新时策略参数已经变了，必须知道“采样这批数据时旧策略有多喜欢这个动作”，才能算新旧策略概率比。

  3. Critic 同时估计当前状态价值

    Critic 输入同一个状态 s_t，输出 V(s_t)。这个 value 会被存进 buffer，后面计算 TD error、GAE、value clipping 都要用。

    价值估计valuet = V(st) Cartpolevalues.shape = [1024]

  4. 环境执行动作并返回反馈

    把动作送给 IsaacLab 环境后，会得到下一个状态、奖励和结束标记。每个并行环境各有一个 reward 和 done。

    环境一步st+1, rt, donet = env.step(at) 奖励形状rewards.shape = [1024] done 形状dones.shape = [1024]

  5. 写入 RolloutBuffer

    每一步都把 obs, action, old_log_prob, reward, done, value 保存下来。采满 num_steps 后，一批 on-policy 数据就准备好了。

    保存数据buffer[t] = {st, at, old_log_probt, rt, donet, V(st)} 采样量num_steps × num_envs = 16 × 1024 = 16384

  6. 用最后一个状态 bootstrap

    rollout 截断在第 16 步时，episode 不一定结束，所以需要 Critic 估计最后状态的价值 V(s_{T})，作为 GAE 反向递推的起点。

    最后价值last_value = V(sT) 形状last_value.shape = [1024]

  7. 反向计算 TD error 和 GAE

    从最后一步往前算。每一步先算 TD error，再用它累积 GAE advantage。这里的 δ_t 不是 state value，而是“TD 预测误差”。

    TD 误差δt = rt + γ · V(st+1) · (1 - donet) - V(st) GAE 递推At = δt + γλ · (1 - donet) · At+1 Returnreturnt = At + V(st)

    直觉：A_t > 0 表示这个动作比 Critic 预期更好；A_t < 0 表示比预期差。Actor 真正吃的是 advantage，不是 reward 原值。

  8. 归一化 Advantage 并 flatten batch

    GAE 得到的 advantage 会被标准化成均值约 0、标准差约 1。然后把时间维和环境维合并，变成 PPO 更新用的大 batch。

    归一化A = A - mean(A)std(A) + 1e-8 obs[16, 1024, 4] → [16384, 4] actions[16, 1024, 1] → [16384, 1] returns[16, 1024] → [16384] advantages[16, 1024] → [16384]

  9. 切 mini-batch，重新评估动作

    更新阶段不会重新采样动作，而是拿 rollout 里旧动作 a_t，问新策略：现在你对这个旧动作的 log 概率是多少？

    重新评估new_log_probt, entropyt, new_valuet = evaluate(st, at) mini-batch16384 / 4 = 4096

  10. 计算新旧策略概率比 ratio

    log 概率相减再 exp，就等价于概率相除。ratio 是 PPO 的核心变量。

    log 形式ratiot = exp(new_log_probt - old_log_probt) 概率形式ratiot = πnew(at|st)πold(at|st)

    ratio = 1 表示新旧策略对这个动作态度一样；ratio = 1.2 表示新策略把这个动作概率提高了 20%；ratio = 0.8 表示降低了 20%。

  11. 计算 PPO clipped policy loss

    普通策略梯度会直接最大化 ratio * advantage。PPO 多做一步裁剪：如果新策略变化太大，就用裁剪后的 ratio，避免一次更新把策略推爆。

    未裁剪surr1 = ratiot · At 裁剪后surr2 = clip(ratiot, 1 - ε, 1 + ε) · At Actor losspolicy_loss = -mean(min(surr1, surr2))

  12. 计算 Critic value loss

    Critic 的目标是让新 value 逼近前面算好的 return_t。工程里常加 clipped value loss，避免 Critic 一步改得太猛。

    未裁剪unclipped = (Vnew(st) - returnt)2 裁剪 valueVclip = Vold(st) + clip(Vnew(st) - Vold(st), -ε, ε) 裁剪损失clipped = (Vclip - returnt)2 Critic lossvalue_loss = 0.5 · mean(max(unclipped, clipped))

  13. 加上 entropy，合成总损失

    entropy 越大，动作分布越分散，探索越强。因为优化器默认最小化 loss，所以 entropy 项前面是负号。

    总损失total_loss = policy_loss + value_coef · value_loss - entropy_coef · entropy

  14. 反向传播、梯度裁剪、更新参数

    Actor、Critic 和 log_std 一起参与反向传播。更新后会把 log_std clamp 到合理范围，避免探索噪声无限变大或变成 0。

    清梯度optimizer.zero_grad() 反传total_loss.backward() 裁剪梯度clip_grad_norm(parameters, max_grad_norm) 更新optimizer.step() 限制噪声log_std = clamp(log_std, min_log_std, max_log_std)

  15. 记录诊断指标

    PPO 训练不要只看 reward。还要看 KL、clip fraction、entropy、action std、value loss 和 explained variance。它们能告诉你策略更新是不是太猛，Critic 有没有学好。

    近似 KLapprox_kl = mean((ratio - 1) - log_ratio) 裁剪比例clip_fraction = mean(abs(ratio - 1) > ε) 解释方差explained_variance = 1 - Var(return - value)Var(return)

PPO 核心代码：最重要的几行

下面不是完整工程版，而是 PPO update 的核心。你只要先看懂这段，PPO 的灵魂就抓住了。

# batch 里保存了 rollout 时的 old_log_probs、actions、advantages、returns dist = actor(states) new_log_probs = dist.log_prob(actions) entropy = dist.entropy().mean() values = critic(states) # 新策略 / 旧策略 的动作概率比 ratio = torch.exp(new_log_probs - old_log_probs) # advantage 通常要归一化，让训练更稳定 advantages = (advantages - advantages.mean()) / (advantages.std() + 1e-8) # PPO clipped objective surr1 = ratio * advantages surr2 = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * advantages policy_loss = -torch.min(surr1, surr2).mean() # Critic 回归 return value_loss = 0.5 * (returns - values).pow(2).mean() # entropy 前面是负号，因为 optimizer 做最小化；我们想最大化 entropy loss = policy_loss + value_coef * value_loss - entropy_coef * entropy optimizer.zero_grad() loss.backward() torch.nn.utils.clip_grad_norm_(parameters, max_grad_norm) optimizer.step()
代码 含义 你要盯住什么
old_log_probs 采样 rollout 时旧策略对动作的 log 概率。 必须保存下来，不能更新后重新算旧概率。
ratio = exp(new - old) 等价于 π_new(a|s) / π_old(a|s)。 如果 ratio 经常远离 1，说明策略变化太猛。
torch.min(surr1, surr2) 选择更保守的那个目标。 这就是 PPO 稳定的核心。
advantages normalize 把 advantage 调成均值 0、方差接近 1。 几乎是 PPO 实战标配，能明显减少训练抖动。

PPO 超参数怎么先记

clip ε

常用 0.1 到 0.3，最常见起点是 0.2。越小越保守，越大更新越激进。

rollout length

每次收集一批连续交互数据。太短 advantage 噪声大，太长更新不够频繁。并行环境常用较大的 batch。

update epochs

同一批数据训练几轮。太少数据利用不足，太多会过拟合旧 rollout，ratio 也容易偏离 1。

学会 PPO 的判断标准：你能解释 old_log_probs 为什么要保存、ratio 为什么是 exp(new-old)、clip 为什么用 min、advantage 为什么要归一化。这四个点通了，PPO 就基本通了。

PPO 里用到的技巧总表

这些技巧不是装饰，它们分别在解决 PPO 训练里的不同不稳定来源：采样切片、价值估计、策略更新过猛、探索不足、梯度爆炸和诊断困难。

技巧 它在做什么 目的 重点观察
并行环境采样 一次同时跑很多个环境，例如 Cartpole 里 num_envs=1024。 快速收集大 batch，降低单条轨迹噪声，让 PPO update 更稳定。 total_fps、reward 曲线是否平滑。
RolloutBuffer 临时保存 obs/actions/rewards/dones/values/old_log_probs。 把“环境交互数据”整理成“神经网络训练 batch”。 shape 是否正确，例如 [16,1024,4] flatten 成 [16384,4]。
保存 old_log_prob 采样时记录旧策略对动作的 log 概率。 更新时计算新旧策略概率比 ratio，这是 PPO clip 的基础。 ratio 是否长期远离 1。
Critic value 用 V(s) 估计当前状态未来折扣回报。 给 Actor 提供低方差的 advantage 信号，也用于 bootstrap。 value_loss、explained_variance。
Bootstrap rollout 截断但 episode 没结束时，用 V(s_T) 补未来价值。 避免把固定长度 rollout 的终点误认为 episode 终点，减少 return 低估。 最后一步 done=False 时是否使用 last_values。
TD error δ = r + γV(s_next)(1-done) - V(s)。 衡量“实际目标”和 Critic 预测的差距，是 GAE 的基本材料。 TD error 是否长期过大，通常会反映到 value loss。
GAE 把多步 TD error 按 γλ 衰减累加成 advantage。 在低方差的一步 TD 和高方差的 Monte Carlo 之间折中。 gae_lambda，常用 0.95。
Advantage 归一化 把 advantage 调成均值约 0、标准差约 1。 让 Actor loss 尺度稳定，减少不同 batch 之间的更新抖动。 训练是否更平滑，policy loss 是否尺度正常。
Mini-batch 多轮更新 同一批 rollout 打乱后切成 mini-batch，重复训练多个 epoch。 提高样本利用率，但仍然保持 on-policy 的约束。 update_epochs、num_mini_batches；太大时 KL 易升高。
Ratio ratio = exp(new_log_prob - old_log_prob)。 衡量新策略相对旧策略对同一动作概率改了多少。 approx_kl、clip_fraction。
PPO policy clip 用 min(ratio*A, clip(ratio)*A) 取保守目标。 限制 Actor 一次更新太猛，避免策略突然崩掉。 clip_fraction 太高说明更新过激。
Clipped value loss 对 V_new - V_old 做裁剪，并取更大的 value loss。 限制 Critic 一步改太大，避免 value function 剧烈漂移。 value_loss、explained_variance。
Entropy bonus 总 loss 里加入 -entropy_coef * entropy。 鼓励探索，防止策略太早变成确定动作。 entropy、action_std_mean。
梯度裁剪 clip_grad_norm(parameters, max_grad_norm) 限制整体梯度 norm。 防止一次反向传播产生过大参数更新，保护训练稳定性。 loss 是否突然爆炸，训练是否出现崩盘。
log_std clamp 把连续动作策略的 log_std 限制在上下界内。 防止探索噪声无限变大或接近 0。 Policy/mean_noise_std 或 action_std_mean。
Approx KL mean((ratio - 1) - log_ratio)。 监控新旧策略距离，常用于自适应调学习率。 是否接近 desired_kl，太高说明策略改太多。
Adaptive learning rate KL 太大就降学习率，KL 太小就升学习率。 让 PPO 更新幅度维持在合理区间。 learning_rate 是否频繁撞上下限。
TensorBoard 指标 记录 reward、length、loss、KL、clip fraction、std、FPS。 让训练不是黑箱，能定位是 Actor、Critic、探索还是性能问题。 Train/*、Loss/*、Policy/*、Perf/*。

快速诊断口诀：reward 看效果，KL 看步子，clip fraction 看是否太猛，entropy/std 看探索，value loss/explained variance 看 Critic，FPS 看仿真吞吐。

实践里最容易踩的坑

Critic 学得太差

如果价值估计很偏，Actor 会被错误信号带跑。常见处理是提高 Critic 更新次数、调小学习率、归一化奖励，或使用 target network。

探索太少

Actor 太快变确定会停止探索。离散动作常加 entropy bonus，连续动作常加噪声或使用随机策略，让模型持续试新动作。

更新步子太大

策略一口气改太多会导致新数据分布突然变化。PPO 的 clipped objective、较小学习率和 advantage normalization 都是在控制这个问题。

现象 可能原因 排查方向
奖励长期不涨 奖励过稀疏、探索不足、学习率不合适。 画 reward 曲线、entropy 曲线、动作分布；先在简单环境验证代码。
Value loss 爆炸 奖励尺度太大、bootstrap 目标不稳定、网络初始化不佳。 奖励缩放或裁剪、梯度裁剪、降低 Critic 学习率。
策略突然崩掉 Actor 更新过大，旧策略和新策略差异太大。 降低学习率，加入 KL 约束或 PPO clipping，增大 batch。

一句话区分几个相关概念

V(s) vs Q(s,a)

V 评价“这个状态平均有多好”；Q 评价“在这个状态做这个动作有多好”。用 V 时 Actor 还要通过采样动作学习，用 Q 时 Critic 更直接评价动作。

On-policy vs Off-policy

A2C、PPO 多是 on-policy，用当前策略采样的数据更新当前策略。DDPG、TD3、SAC 多是 off-policy，可以利用 replay buffer 里的旧数据。

离散 vs 连续动作

离散动作 Actor 常输出 softmax 概率；连续动作 Actor 常输出高斯分布的均值和方差，或直接输出确定性动作。

Actor 负责变得更会选，Critic 负责变得更会看。两者一起，强化学习就从“蒙着眼试错”变成了“带反馈地练习”。
